# Multi_omics_DeltaTMS_Prediction_Model

This project evaluates **single-omics** and **multi-omics early-fusion** machine-learning models for predicting `DeltaTMS` using CSF and serum measurements collected at multiple timepoints.

The pipeline is designed to separate model development from held-out evaluation and to perform target-aware preprocessing and feature selection inside the training folds whenever possible.

---

## 1. Project Workflow

```text
1. Preprocessing
- Raw omics + metadata (data_filtering.ipynb)
- Filter Patient-level / timepoint-specific feature tables

2-1. Single-Omics                  
- Nested-CV Training
- Training-based
- model selection 
- Test

2-2. Early Fusion Multi-Omics
- Nested-CV Training
- Training-based 
- model selection             
- Test
```

---

## 2. Omics Definitions

Two tissue types are analyzed:

* `CSF`
* `Serum`

Timepoints:

* 24 h
* 48 h
* 72 h
* 96 h
* 120 h

The prediction target is `DeltaTMS`.

---

# 3. Data Preparation

Notebook:

```text
data_filtering.ipynb
```

The preprocessing notebook converts the raw omics matrices into patient-level, timepoint-specific feature tables.

### Main preprocessing steps

1. Load metabolomics, proteomics, and miRNA matrices and metadata.
2. Replace extremely low assay values with missing values.
3. Transpose the original feature-by-sample matrices into sample-by-feature matrices.
4. Align omics measurements with patient metadata.
5. Aggregate repeated measurements at the patient level using the mean.
6. Construct timepoint-specific features.
7. Generate adjacent timepoint-difference features.
8. Construct the target variable `DeltaTMS`.
9. Generate clinical covariates:
   * Age
   * Gender
   * Level
10. Build single-omics and multi-omics combination tables.

# 4. Single-Omics Modeling

## 4.1 Single-Omics Training

Notebook:

```text
single_omics_Training.ipynb
```

Single-omics models are evaluated separately for:

```text
A = Proteomics
B = Metabolomics
C = miRNA
```

The current experiment uses the clinical mode, which adds:

```text
Age + Gender + Level
```

to the omics features.

### Cross-validation design

The training notebook uses nested cross-validation:

```text
Outer CV: 5 folds
Inner CV: 3 folds
```

The outer folds produce the final training Predictions, while the inner folds are used for hyperparameter and model selection.

The primary training metric is:

```text
R²
```

rather than full-training R².

### Candidate models

The current Single-Omics model search includes:

* Ridge
* Elastic Net
* PLS
* Linear SVR
* Gradient Boosting Regressor
* XGBoost

### Feature selection

Feature selection is performed inside the training folds using:

```text
corr_topk
f_regression_topk
```

The feature weighting step uses train-side univariate association scores and applies mild weights between:

```text
1.0 and 1.2
```

# 5. Multi-Omics Early Fusion

## 5.1 Early Fusion Definition

Early Fusion combines the three omics blocks into a single feature matrix before model fitting:

```text
Proteomics
     +
Metabolomics
     +
miRNA
     |
     v
ABC feature matrix
     |
     v
Feature selection
     |
     v
Regression model
```

This differs from Single-Omics modeling because all three omics sources are available to the same model.

---

## 5.2 Early Fusion Training

Notebook:

```text
multi_omics_ef_cv_Training.ipynb
```

The Early Fusion experiment uses:

```text
ABC = Proteomics + Metabolomics + miRNA
```

and evaluates two clinical modes:

```text
omics_only
light
```

where `light` includes:

```text
Age + Gender + Level
```

### Nested CV

The EF training pipeline uses:

```text
Outer CV = 5 folds
Inner CV = 3 folds
```

The outer folds provide OOF predictions and the inner folds select model hyperparameters, feature-selection settings, and feature-weight settings.

### Feature Selection

The current EF experiment uses:

```text
f_regression_topk
```

A block-aware preselection stage attempts to allocate features across:

```text
PROT
MET
RNA
```

with a minimum quota for each available block.

### Feature Weighting

Two weighting modes are evaluated:

```text
none
soft
```

The `soft` mode maps train-side feature scores to weights between:

```text
1.0 and 1.2
```

### Stability-Aware Inner-CV Objective

Instead of selecting a configuration using only mean inner-fold R², the EF code uses:

```text
selection_score =
    mean_inner_r2
    - 0.50 * std_inner_r2
    + 0.20 * min_inner_r2
```

This penalizes unstable configurations and rewards models that maintain reasonable performance across all folds.

# 6. Leakage Control

The modeling notebooks explicitly separate training and held-out testing.

Target-aware operations such as:

* feature selection,
* feature weighting,
* hyperparameter tuning,

are performed using training data.

During nested CV, feature selection is recomputed inside the inner training folds.

The held-out test labels are not used for final model selection.

For the Single-Omics Top-N sensitivity analysis, multiple training-selected candidates are evaluated on the test set, but the resulting test ranking is descriptive only. The final reported configuration remains the model selected from training CV.

# 7. Important Implementation Notes

### Single-Omics Top-K Semantics

The current Single-Omics implementation subtracts the number of protected encoded clinical features from `top_k`.

Therefore, when the number of encoded clinical features is greater than or equal to `top_k`, the final feature set can contain only clinical variables and no omics variables.

This particularly affects small Top-K configurations such as:

```text
Top-K = 5
Top-K = 10
Top-K = 15
```

when `light` clinical mode produces approximately 16 encoded clinical columns.

This behavior should be reviewed before interpreting these runs as omics-based models.

### Early-Fusion Blockwise Selection

Early Fusion initially applies blockwise feature allocation across proteomics, metabolomics, and miRNA.

However, the subsequent global `top_k` reduction reranks the preselected features together. Therefore, the final feature set is not strictly guaranteed to retain features from every omics block.

If preservation of all omics blocks is required, the final Top-K step should also be block-aware.

# 9. Evaluation Metrics

### R²

Higher is better.

```text
R² = 1
```

indicates perfect predictions.

```text
R² = 0
```

indicates performance equivalent to predicting the mean target value.

```text
R² < 0
```

indicates worse performance than the mean-prediction baseline.

### MAE

Mean Absolute Error measures the average absolute prediction error.

Lower MAE indicates better predictive accuracy.

For model development, this project primarily uses **OOF R²** as the training performance metric and **held-out Test R²** as the final generalization metric.
